# NAEDA 포팅 및 시연 매뉴얼

## 0. 문서 개요

이 문서는 `C:\SSAFY\S14P21D103` 저장소를 기준으로, GitLab 소스 클론 이후 로컬 환경에서 빌드/실행/시연할 수 있도록 정리한 포팅 문서다.

실제 실행 대상 애플리케이션 폴더는 아래 5개다.

- `naeda` : Spring Boot 백엔드
- `AI` : FastAPI AI 서버
- `naedafront` : 사용자 Android 앱
- `naedaterminal` : 매장 단말기 Android 앱
- `naedapos` : 웹 POS

단, 위 5개만 실행하면 되는 구조는 맞지만, `naeda`가 아래 외부 인프라에 의존하므로 실행 전 함께 준비해야 한다.

- PostgreSQL
- Redis
- Kafka
- Zookeeper

권장 시연 장비 구성은 아래와 같다.

- PC 브라우저 1대 : `naedapos`
- Android 기기/에뮬레이터 1대 : `naedaterminal`
- Android 기기/에뮬레이터 1대 : `naedafront`

중요 전제:

- 저장소 안에는 시연 계정 `경훈`, `도영`을 생성하는 SQL이 포함되어 있지 않다.
- 따라서 해당 계정은 시연용 DB에 사전 생성되어 있어야 한다.
- 특히 `도영` 계정은 소비패턴분석과 포인트 상점 시연을 위해 결제 이력과 포인트가 미리 누적되어 있어야 한다.

### 1.4 배포 및 실행 시 특이사항

#### 1.4.1 현재 코드 기준이 README보다 우선이다

일부 README에는 과거 값이 남아 있다. 실제 포팅 기준은 아래 파일이 우선이다.

- `naeda/src/main/resources/application.yaml`
- `AI/.env.example`
- `naedafront/app/build.gradle.kts`
- `naedaterminal/app/src/main/java/com/example/naedaterminal/MainActivity.kt`
- `naedapos/vite.config.js`

#### 1.4.2 `naeda/docker-compose.yml`에는 Redis가 포함되어 있지 않다

`naeda/docker-compose.yml`은 PostgreSQL, Kafka, Zookeeper만 포함한다. Redis는 별도 실행이 필요하다.

#### 1.4.3 Android 앱과 POS는 기본값이 원격 서버로 하드코딩되어 있다

로컬 포팅 시 반드시 URL을 바꿔야 한다. 수정하지 않으면 로컬 서버를 띄워도 앱은 계속 원격 배포 서버를 바라본다.

#### 1.4.4 `POS Key`는 사실상 `storeId`다

`naedaterminal` 첫 화면은 `POS Key` 입력으로 보이지만, 코드상 실제로는 `storeId`를 저장하고 사용한다.

즉, 아래 값은 반드시 동일해야 한다.

- `naedapos`의 `매장 ID`
- `naedaterminal`의 `POS Key`

#### 1.4.5 시연 시나리오상 `도영` 계정은 사전 데이터가 필요하다

아래 두 기능은 실시간으로 결제 한 번만 해서 만들기 어렵다.

- 소비패턴분석
- 포인트 상점

따라서 `도영` 계정에는 아래 데이터가 미리 있어야 한다.

- 과거 결제 이력
- 월간 소비 분석이 나올 정도의 카테고리별 지출
- 포인트 지갑
- 사용 가능한 포인트

#### 1.4.6 `경훈` 계정의 페이스페이 등록은 신분증 OCR 검증을 통과해야 한다

페이스페이 등록 과정에서는 로그인한 계정 정보와 촬영한 신분증 정보가 비교된다. 따라서 아래 둘 중 하나가 필요하다.

- `경훈` 계정 실사용 정보와 일치하는 신분증
- 이미 등록된 시연용 DB/계정 환경

### 2.1 외부 서비스 현황

이 프로젝트는 소셜 로그인은 사용하지 않는다. 대신 아래 외부 서비스/API/SDK에 의존한다.

| 서비스 | 용도 | 필요한 정보 | 설정 위치 | 없을 때 영향 |
|---|---|---|---|---|
| SSAFY 금융 API | 회원가입, 계좌 조회, 카드 조회, 결제 | `SSAFY_API_KEY` | `naeda/.env`, `application.yaml` | 핵심 금융 기능 실패 |
| OpenAI API | AI 챗봇 응답 생성 | `OPENAI_API_KEY`, `OPENAI_MODEL` | `AI/.env` | 챗봇 실패 |
| SSAFY GMS 프록시 | OpenAI 호출 프록시 | 별도 URL 코드 내 고정 | `AI/app/services/chat_service.py` | 챗봇 실패 |
| Naver Search API | 매장 보강/검색 | `NAVER_SEARCH_CLIENT_ID`, `NAVER_SEARCH_CLIENT_SECRET` | `naeda/.env`, `application.yaml` | 매장 부가정보 수집 제한 |
| Naver Maps SDK | 지도 화면 | `NAVER_MAPS_KEY_ID`, `NAVER_MAPS_KEY` | `naedafront/app/build.gradle.kts` | 지도 표시 불가 |
| Firebase Cloud Messaging | 푸시 알림 | `google-services.json`, 서비스 계정 JSON | `naedafront`, `naeda` | 푸시 불가, 나머지 기능은 대부분 동작 |

### 2.2 빌드/실행 시 필요한 외부 저장소와 네트워크

| 외부 자원 | 용도 |
|---|---|
| `services.gradle.org` | Gradle Wrapper 다운로드 |

| Docker Hub | Postgres, Redis, Kafka, Zookeeper 이미지 다운로드 |

외부망이 막혀 있으면 아래 작업이 실패할 수 있다.

- Gradle Wrapper 최초 다운로드
- `npm install`
- `pip install -r requirements.txt`
- Docker 이미지 pull

## 3. DB 덤프 파일 최신본

### 3.1 현재 저장소 기준 결론

현재 저장소에는 운영/시연 DB 전체를 그대로 복원하는 `.dump`, `.bak`, 전체 시연용 계정 SQL 파일은 포함되어 있지 않다.

즉, 저장소 기준으로 확인 가능한 최신 DB 자산은 "덤프 파일"이라기보다 아래 초기화/정의용 SQL 파일들이다.

### 3.2 저장소 내 최신 DB 자산 목록

| 파일 경로 | 역할 |
|---|---|
| `naeda/db/schema.sql` | 메인 테이블 생성 DDL |
| `infra/init/01_schema.sql` | Docker 초기화용 스키마 |
| `infra/init/02_dummy_user.sql` | 더미 사용자 시드 |
| `docs/erd/erd.sql` | ERD 참조 SQL |
| `naeda/db/manual_migrations/20260316_store_identity_refactor.sql` | 수동 마이그레이션 |

### 3.3 시연 계정 관점의 주의사항

- 저장소에는 `경훈`, `도영` 계정을 넣는 SQL이 없다.
- 따라서 아래 둘 중 하나가 필요하다.

1. 별도 시연용 DB 덤프를 운영자가 따로 보관 중인 경우, 해당 덤프를 직접 복원
2. 로컬 DB에서 회원가입과 데이터 적재를 통해 시연 계정을 사전 준비

특히 아래 조건이 충족되어야 본 문서의 시연 시나리오가 그대로 가능하다.

- `경훈` : 로그인 가능, 페이스페이 등록 전 상태 또는 재등록 가능한 상태
- `도영` : 로그인 가능, 소비 분석용 결제 데이터 보유, 포인트 지갑 및 포인트 보유

## 4. 시연 시나리오

### 4.1 시연 전 공통 준비

시연 시작 전에 아래를 먼저 맞춘다.

1. `naeda`, `AI`, `naedapos`, `naedaterminal`, `naedafront`가 모두 실행 중이어야 한다.
2. `naedapos`의 `매장 ID`와 `naedaterminal`의 `POS Key`는 같은 값이어야 한다.
3. `naedapos`에는 결제 요청 생성이 가능한 상태여야 한다.
4. `naedapos`에 JWT 토큰이 세팅되어 있어야 한다.
5. `경훈`, `도영` 계정은 시연 DB에 미리 존재해야 한다.
6. `도영` 계정은 소비패턴분석/포인트 상점용 데이터가 사전 적재돼 있어야 한다.
7. `경훈` 계정은 신분증 OCR 검증이 가능한 정보가 준비돼 있어야 한다.
8. 사용자 앱과 단말기 앱 모두 카메라 권한을 허용해야 한다.

권장 시연 배치:

- 브라우저: `naedapos`
- 단말기: `naedaterminal`
- 사용자 휴대폰: `naedafront`

### 4.2 시연 1. `(계정 : 경훈) 페이스페이 등록`

사전 상태:

- `naedafront`에서 `경훈` 계정으로 로그인
- 아직 페이스페이가 등록되지 않았거나, 재등록 가능한 상태

화면 동선:

1. `홈` 탭 진입
2. 홈 중간의 페이스페이 배너에서 `페이스 페이 설정` 터치
3. 등록 플로우 화면에서 `페이스페이 시작하기` 또는 `등록 시작하기` 터치
4. 얼굴 촬영 가이드에 따라 얼굴 등록 진행
5. 주민등록증 또는 운전면허증 촬영 진행
6. OCR 결과 확인 후 계정 정보 일치 여부 확인
7. 대표 결제수단(계좌 또는 카드) 선택
8. 필요 시 PIN 인증/설정 진행
9. 완료 화면에서 등록 성공 확인

시연 포인트:

- "얼굴 등록 한 번으로 결제 끝" 배너가 등록 완료 상태로 바뀌는지 확인
- 필요 시 홈 화면에서 `페이스페이 등록 완료`, `페이스페이 결제 시 5% 적립` 문구를 보여준다

### 4.3 시연 2. `(계정 : 경훈) 결제 후 입출금 내역 확인`

사전 상태:

- `경훈` 계정의 페이스페이 등록 완료
- `naedapos`와 `naedaterminal`이 같은 `storeId`로 연결됨

결제 동선:

1. 브라우저 `naedapos`에서 메뉴 1개 이상 선택
2. 하단 우측 `페이스페이` 버튼 클릭
3. `naedaterminal` 대기 화면에서 `결제 요청 수신!` 확인
4. 단말기에서 `페이스페이 결제` 화면 확인 후 `얼굴 인식 시작` 터치
5. `경훈`이 단말기 카메라 앞에서 얼굴 인증 진행
6. RBA 정책상 PIN이 요구되면 등록한 6자리 PIN 입력
7. 단말기에서 `결제가 완료되었습니다` 확인
8. POS 상태창에서 `SUCCESS` 확인

입출금 내역 확인 동선:

1. `naedafront`에서 여전히 `경훈` 로그인 상태 유지
2. 하단 `지갑` 탭 이동
3. 계좌 또는 카드 항목 선택
4. 상세 화면에서 가장 최근 거래 내역 확인

확인 포인트:

- 결제 직후 최신 내역이 보여야 한다
- 거래 부제목/카테고리에는 `OOOO 페이스페이 결제` 같은 메모가 아니라 실제 카테고리명이 보여야 한다
- 예시는 `한식`, `중식`, `일식`, `카페`, `분식` 등 매장 카테고리 기준이다

### 4.4 시연 3. `(계정 : 도영) 소비패턴분석 보여주기`

사전 상태:

- `도영` 계정에 과거 결제 데이터가 누적되어 있어야 함

화면 동선:

1. `경훈` 계정에서 로그아웃
2. `도영` 계정으로 로그인
3. `홈` 탭으로 이동
4. 화면을 아래로 내려 `소비 분석` 섹션 확인

설명 포인트:

- 가장 많이 지출한 카테고리
- 해당 카테고리 금액
- 카테고리별 비중 막대
- AI 소비 인사이트 문장

주의:

- 데이터가 없으면 `아직 소비 데이터가 없어요` 상태만 노출된다
- 따라서 이 단계는 반드시 사전 적재된 `도영` 계정으로 시연해야 한다

### 4.5 시연 4. `(계정 : 도영) AI 챗봇 보여주기`

화면 동선:

1. `도영` 계정 로그인 상태에서 `홈` 탭 유지
2. 우하단 말풍선 형태의 `AI 챗봇` 버튼 터치
3. 챗봇 화면 진입 후 입력창에 아래 문장 입력

```text
구미 진평동 4명 회식 장소 추천해줘.
```

4. 답변 생성 결과 확인

설명 포인트:

- 챗봇 캐릭터 `토미봇`
- 구미 지역 기반 추천 질의 응답
- 맛집/카페/축제/생활 정보 응답 가능

사전 조건:

- `AI/.env`에 `OPENAI_API_KEY`가 정상 설정되어 있어야 한다

### 4.6 시연 5. `(계정 : 도영) 포인트 상점 구경`

사전 상태:

- `도영` 계정에 포인트 지갑과 포인트가 있어야 보기 좋다

화면 동선:

1. 하단 탭 `상점` 이동
2. 상단 `포인트 스토어` 헤더에서 현재 포인트 확인
3. 필요하면 우측 `내역보기` 터치 후 포인트 적립 내역 확인
4. 다시 상점 메인으로 돌아와 카테고리 탭을 가볍게 이동

추천 설명 멘트:

- "페이스페이 결제 시 포인트가 적립됩니다."
- "쌓인 포인트로 구미 바우처, 식음료, 디지털 상품 등을 교환할 수 있습니다."

실행 포인트:

- 구매까지 할 필요는 없고, 상점 진입과 상품 리스트 확인 정도면 충분하다

### 4.7 시연 6. `(계정 : 도영) 지도, 맛집 구경`

화면 동선:

1. 하단 탭 `지도` 이동
2. 필요 시 위치 권한 허용
3. 우측 또는 상단의 `지도 필터` 버튼 진입
4. `페이스페이 매장만 보기` 활성화
5. 필요하면 카테고리를 `한식` 등으로 선택
6. 구미 지도에서 지역을 선택하거나 맛집 리스트 확인
7. 지역 하단 시트의 `맛집 리스트`를 보여준다

추천 설명 멘트:

- "구미 지역 맛집을 지도 기반으로 볼 수 있습니다."
- "페이스페이 가능한 매장만 필터링해서 볼 수 있습니다."

시연 포인트:

- 지도 필터에서 `페이스페이 매장만 보기`를 직접 켜는 장면
- 지역별 맛집 리스트가 하단 시트로 뜨는 장면

### 4.8 계정 전환 방법

`경훈`에서 `도영`으로 바꿀 때는 아래 순서를 사용한다.

1. 홈 우상단 프로필 또는 마이페이지 진입
2. `로그아웃` 선택
3. 로그인 화면으로 이동
4. `도영` 계정으로 재로그인

## 6. 트러블슈팅

### 6.1 Android 앱이 로컬 서버가 아니라 배포 서버를 본다

원인:

- `naedafront`, `naedaterminal`, `naedapos` 기본 URL이 원격 서버로 하드코딩되어 있음

조치:

- `naedafront/app/build.gradle.kts`
- `naedaterminal/app/src/main/java/com/example/naedaterminal/MainActivity.kt`
- `naedapos/vite.config.js`

를 로컬 주소로 수정한다.

### 6.2 결제 요청이 POS에서는 생성되는데 단말기에서 못 잡는다

확인 항목:

- POS `매장 ID`와 단말기 `POS Key`가 같은지
- 단말기 `apiBaseUrl`이 로컬 백엔드를 보는지
- 백엔드 `/api/pay-requests?storeId=...` 응답이 정상인지

### 6.3 챗봇이 응답하지 않는다

확인 항목:

- `AI/.env`의 `OPENAI_API_KEY`
- `AI/.env`의 `DATABASE_URL`
- `AI` 서버 기동 상태

### 6.4 소비 분석이 비어 있다

원인:

- 해당 사용자에게 충분한 결제 데이터가 없음

조치:

- 시연용 계정 `도영`에 기존 결제 데이터가 들어 있는 DB를 사용하거나, 사전 적재를 수행한다

### 6.5 포인트 상점이 비어 보인다

원인:

- 포인트 지갑이 아직 생성되지 않았거나 포인트가 없음

조치:

- 시연 전에 포인트 적립 이력을 넣은 계정을 사용한다

### 6.6 회원가입, 계좌조회, 카드조회, 결제가 실패한다

원인:

- `SSAFY_API_KEY` 미설정 또는 외부 SSAFY API 호출 실패

조치:

- `naeda/.env`와 `application.yaml` 기준 설정을 재확인한다
