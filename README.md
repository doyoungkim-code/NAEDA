## 1. 프로젝트 개요

### 1.1 프로젝트명

고민중..

### 1.2 한 줄 소개

페이스페이로 결제할 때마다 포인트가 쌓이고, AI가 소비를 분석해주고, 모은 포인트로 구미 지역에 후원하거나 할인권으로 교환하는 **지역 특화 금융 앱**

### 1.3 프로젝트 배경

### 💡 출발점: "몸만 나왔는데 결제를 못 한다"

누구나 한 번쯤 겪어본 상황이 있다:

- 점심시간에 지갑을 두고 나와서 편의점에서 물 한 병을 못 사는 경우
- 카드를 꺼내고, 단말기에 대고, 비밀번호 누르고... 매번 반복되는 결제 과정

**"내 얼굴만 있으면 결제할 수 있다면?"** 이라는 단순한 질문에서 프로젝트가 시작되었다.

### 📊 시장 환경: 얼굴 결제 시대의 도래

- 2025년 토스 페이스페이 정식 출시, 가입자 85만+, 가맹점 20만+ 돌파
- 2026년 100만 가맹점 목표 등 얼굴 인식 결제가 차세대 핀테크 트렌드로 부상
- 그러나 기존 페이스페이는 "결제"에서 끝남 — 지역경제 활성화, 사회공헌과의 연결은 부재

### 🌱 우리의 방향: 결제를 넘어 선한 영향력으로

- 얼굴 결제의 편리함을 기반으로, 구미 지역경제 활성화 연결
- "결제가 곧 선한 영향력이 되는" 구미 지역 특화 금융 앱을 기획

### 1.4 핵심 차별화 포인트

| 구분 | 토스 페이스페이 | 페이스 굿 구미 (우리) |
| --- | --- | --- |
| 범위 | 전국 | 구미 지역 특화 |
| 인증 | 얼굴 + FDS 기반 동적 이중인증 | 얼굴 + RBA(금액/유사도 기반 단계 인증) |
| 쌍둥이 대응 | 자체 2차 인증 방식으로 대응 | 전화번호 보조 인증으로 오인식 차단 |
| 지역화폐 | 미지원 | 얼굴로 지역화폐 결제 |
| 지역 데이터 | 없음 | 구미 상권 소비 분석 제공 |
| AI 분석 | 없음 (FDS만 있음) | 소비 분석 + 맛집 추천 + FDS |

## 4. 핵심 기능 상세

### 4.1 기본 뱅킹 (SSAFY 금융 API 기반)

- 계좌 조회, 이체, 거래 내역 조회 (**SSAFY 수시 입출금 API**)
- 잔액 관리, 입출금 알림
- 카드 결제 내역 조회 (**SSAFY 카드 API**)
- 1원 송금 본인 인증 (**SSAFY 인증 API**)
- 결제 시 1회/ 1일 한도값 설정

### 4.2 페이스페이 결제

- **등록:** 사용자 앱에서 다각도 얼굴 촬영 → 서버에 128차원 얼굴 벡터 암호화 저장 (원본 이미지 미저장)
- **결제:** 매장 단말기 앱에서 카메라 촬영 → Passive Liveness 검증 → 얼굴 벡터 추출 → 서버 매칭 → **SSAFY 카드 API** 결제 처리
- **Liveness Detection 순서:**

```
1. 카메라 촬영
2. Passive Liveness 검증 (눈 깜빡임 + 고개 방향) ← 매칭 전에 먼저 수행
3. 통과 시 → 얼굴 벡터 추출 → DB 매칭
4. 매칭 성공 → 결제 실행
```

> Passive Liveness를 얼굴 매칭 "전에" 수행. 위조 공격을 매칭 단계 전에 걸러야 서버 부하도 줄고 보안도 강화됨.

### 4.2.1 매장 단말기 결제 플로우

매장 단말기 앱은 기존 포스기와 연동되는 결제 수단 선택 화면을 제공:

```
포스기에서 결제 금액 전달
  → 단말기 앱: 결제 수단 선택 화면
    ├── 카드         (UI만, 미구현)
    ├── 카카오페이    (UI만, 미구현)
    ├── 삼성페이      (UI만, 미구현)
    └── 페이스페이    (실제 동작)
          → 카메라 얼굴 인식
          → Liveness → 매칭 → 결제
          → (필요 시) 2차 비밀번호 입력 화면
          → 결제 결과 화면
```

> ※ 카드/카카오페이/삼성페이는 UI만 구성. 상용화 시 확장 가능한 구조로 설계.
※ 데모 시 결제 금액은 하드코딩 또는 서버 전달 방식으로 처리.
> 

### 4.3 리스크 기반 인증(RBA) 체계

기본 인증은 얼굴 인식이며, 금액과 유사도에 따라 인증 단계를 강화:

| 금액 | 인증 | 추가 |
| --- | --- | --- |
| 5만원 미만 | 얼굴 | 없음 |
| 5만원 이상 | 얼굴 | 전자 서명 |

**얼굴 유사도 기반 단계 인증:**

```
유사도 80 이상:
  → 바로 결제

유사도 70~79:
  → 전화번호 가운데 4자리 확인 후 결제

완전 실패:
  → 전화번호 조회
  → 계정 없으면 결제 차단 / 계정 생성 요청
  → 계정 있으면 결제 차단 / 얼굴 재등록 요청
```

### 4.3.1 FCM 알림

- 결제 완료 즉시 휴대폰 푸시 알림 발송
- 축제 예정/이벤트 일정이 있을 경우 FCM 공지 알림 발송

### 4.4 AI 이상 거래 탐지 (FDS)

- **1차 필터: 규칙 기반 엔진** — 즉시 탐지가 필요한 명확한 패턴
- **2차 필터: 통계적 이상 탐지 (Isolation Forest)** — 사용자별 정상 패턴을 학습하고, 이탈 거래를 이상 점수(Anomaly Score)로 산출
- 이상 점수 기반 대응:

| 점수 구간 | 대응 |
| --- | --- |
| 0~30 (정상) | 로그만 기록 |
| 30~60 (주의) | 앱 알림: "방금 결제가 본인이 맞나요?" |
| 60~80 (경고) | 결제 일시 정지 + 본인 확인 요청 |
| 80~100 (위험) | 결제 차단 + 긴급 알림 |
- FDS 규칙 예시:

| 탐지 규칙 | 설명 | 대응 |
| --- | --- | --- |
| 시간대 이상 | 심야(00:00~06:00) 고액 결제 | 본인 확인 추가 요청 |
| 지역 이상 | 평소 활동 반경 외 결제 | 앱 알림 + 확인 요청 |
| 빈도 이상 | 10분 내 3회 이상 연속 결제 | 일시 정지 + 알림 |
| 금액 이상 | 일일 평균의 300% 초과 결제 | 이중 인증 강제 적용 |

### 4.5 구미 맛집/카페/관광지/축제 리스트

- 식당/카페/관광지 페이스페이 가능 매장 필터링해서 보여주기
- 관광지와 예정된 축제를 소개해줌
- 축제가 다가올때 fcm으로 공지 전달

### 4.6 AI 소비 분석 및 인사이트

- 카테고리별 소비 패턴 분석 (식비, 카페, 교통, 쇼핑 등)
    - **가맹점명 → 카테고리 자동 분류:** 규칙 기반 매칭(정확한 가맹점) + NLP 텍스트 분류(애매한 가맹점)
    - **거래 내역 메모 API**로 AI 분류 태그 자동 저장
- 주간/월간 소비 리포트 자동 생성
- 절약 인사이트 제공
    - 예: "이번 달 외식비 전월 대비 +23%, 줄이면 월 3만원 절약 가능"
- 구미 지역 소비 비율 분석
    - 예: "이번 달 지역 소비 62%, 지역경제 기여 점수 A!"
    - 지역 소비 비율이 높을수록 추가 포인트 보너스

### 4.7 포인트 시스템

| 구분 | 상세 |
| --- | --- |
| 기본 적립 | 결제 금액 1,000원당 10P 적립 |
| 지역 보너스 | 구미 지역 소상공인 매장 결제 시 2배 적립 (20P) |
| 사용 - 할인권 | 5,000P = 5,000원 지역 상품권, 지역 카페 기프티콘, 구미시 굿즈 등 교환 가능 |

## 7. 결제 보안 구조

### 7.1 3단계 보안 레이어

| 단계 | 기술 | 차단 대상 |
| --- | --- | --- |
| 1단계: Liveness Detection | MediaPipe EAR 눈 깜빡임 + 랜덤 고개 방향 | 사진, 영상, 인쇄물 위조 공격 |
| 2단계: 얼굴 매칭 | face_recognition 128차원 벡터 비교 (tolerance 0.6, 조정 가능) | 타인의 결제 시도 |
| 3단계: 보조 인증 | 전자 서명 + 전화번호/PIN 보조 인증 | 고액 결제, 경계 유사도, 오인식 상황 |

> Liveness → 얼굴 매칭 순서로 수행 (위조를 먼저 걸러야 서버 부하 감소 + 보안 강화)
> 

> 임계값 0.6(face_recognition 기본값)에서 시작. 실제 테스트 후 0.4~0.6 사이에서 최적값 튜닝.
> 

### 7.2 결제 플로우

**일반 결제 (5만원 미만):**

```
매장 단말기 앱: 페이스페이 선택
  → CameraX 카메라 촬영
  → Liveness 검증 (눈 깜빡임 + 고개 방향)
  → 통과 → 얼굴 벡터 추출 → DB 매칭 (유사도 확인)
  → 유사도 80 이상: 즉시 결제
  → 유사도 70~79: 전화번호 가운데 4자리 확인 후 결제
  → 완전 실패: 결제 차단 + 계정 조회/얼굴 재등록 유도
```

**고액 결제 (5만원 이상):**

```

  → CameraX 카메라 촬영

  → 전자 서명 요구
```

## 8. 구미시 지역 특화 전략

### 8.1 지역경제 활성화 구조

```
[소비자]                    [소상공인]                  [지역사회]
 얼굴로 결제                매장 노출 증대              지역 상품권 활성
 포인트 2배 적립            단골 고객 확보               지역경제 순환
 맛집 추천 받기             매출 데이터 분석             
      │                         │                          │
      └─────────── 선순환 구조 ─────────────────────────────┘
```

- 구미 지역 소상공인 매장 결제 시 포인트 2배 적립으로 지역 소비 유도
- AI가 구미 지역 맛집/카페를 우선 추천하여 소상공인 매장 노출 증대
- 포인트 지역 상품권, 기프티콘 등을 구미 지역 매장 전용으로 설계하여 지역 내 소비 순환 촉진

### 8.2 지역화폐 연계

- **포인트 = 구미 지역 전용 화폐** 역할
- SSAFY 수시 입출금 API의 별도 계좌를 **"구미페이 포인트 지갑"**으로 활용
- 구미 지역 매장에서만 사용 가능 → 지역 내 소비 순환

### 8.3 구미 맛집/카페 AI 추천 로직

- **콘텐츠 기반 필터링:** 사용자 소비 이력 → 카테고리 선호도 벡터 → 매장 벡터와 코사인 유사도
- 시간대별 추천 (점심: 식당, 오후: 카페, 저녁: 회식 장소)
- 날씨 연동 (추운 날: 국물 요리, 더운 날: 냉면/빙수)
- 방문 이력 반영 (재방문 vs 새로운 매장 밸런스)
- 구미 지역 소상공인 매장 가산점 부여

### 12.1 기술적 의의

- 얼굴 인식(CV) + AI 분석(ML) + 보안 인증 설계(RBA) + 네이티브 Android(Compose) + Spring Boot + FastAPI **MSA 기반 4개 기술 도메인 통합**

- **SSAFY 금융 API 8개 이상 활용**으로 실제 금융 서비스 개발 경험
- Spring Boot(메인) + FastAPI(AI) **마이크로서비스 아키텍처 적용**

### 12.2 사회적 의의

- 구미 지역 소상공인 매출 증대 및 지역경제 순환 구조 구축
