# AI 담당자 체크리스트

## 0. 역할 정의
- [ ] AI 담당 역할을 팀에 명확히 공유했다.
- [ ] AI 서비스 범위를 `이미지 -> 임베딩(512)`로 확정했다.
- [ ] Back 책임(저장/유사도 검색/최종 판정)과 경계를 확정했다.

## 1. 착수 전 합의
### 1.1 API 계약
- [ ] Back과 내부 API 경로를 확정했다. (`POST /internal/v1/embeddings/extract`)
- [ ] 요청 형식을 확정했다. (`multipart/form-data`, `image`)
- [ ] 응답 형식을 확정했다. (`embedding`, `dim`, `model`, `faceCount`)
- [ ] 에러코드 표준을 확정했다. (`EMPTY_IMAGE`, `INVALID_IMAGE`, `NO_FACE`, `MULTIPLE_FACES`, `AI_TIMEOUT`, `AI_UNAVAILABLE`)

### 1.2 성능/SLA
- [ ] 목표 latency(p95), timeout, 처리량(QPS)을 수치로 합의했다.
- [ ] Front 전송 정책(예: 최대 10fps)과 Back 재시도 정책을 합의했다.

### 1.3 보안/개인정보
- [ ] 원본 이미지 디스크 저장 금지 원칙을 문서화했다.
- [ ] 요청/응답 로그 마스킹 정책을 확정했다.
- [ ] 내부 호출 인증 방식(서비스 토큰/mTLS)을 확정했다.

## 2. 개발 환경 준비
- [ ] Python 버전과 의존성 버전을 고정했다. (`requirements.txt`)
- [ ] 모델명/프로바이더 환경변수를 정리했다. (`ARCFACE_MODEL_NAME`, `ARCFACE_PROVIDER`)
- [ ] 로컬 실행 스크립트를 정리했다. (`start.ps1`/`start.cmd`)
- [ ] `.env.example`를 최신값으로 유지했다.

## 3. 핵심 추론 구현
### 3.1 전처리/검증
- [ ] 이미지 바이트 읽기 실패 처리를 구현했다.
- [ ] 이미지 디코딩 실패 처리를 구현했다.
- [ ] 얼굴 0개/2개 이상 입력에 대한 에러 처리를 구현했다.

### 3.2 임베딩 생성
- [ ] ArcFace 모델을 앱 시작 시 1회 로딩하도록 구현했다.
- [ ] 임베딩 길이(512) 검증을 구현했다.
- [ ] L2 정규화 후 반환하도록 구현했다.

### 3.3 API 응답
- [ ] 성공 응답 JSON 스키마를 계약과 일치시켰다.
- [ ] 실패 응답 JSON 스키마를 계약과 일치시켰다.
- [ ] HTTP 상태코드를 케이스별로 일관되게 반환한다.

## 4. Back 연동 지원
- [ ] Back에서 바로 호출 가능한 예시 요청(cURL/Postman)을 제공했다.
- [ ] Back 에러 매핑 가이드를 작성했다. (AI 에러 -> Back 도메인 에러)
- [ ] timeout/retry 권장값을 Back 팀에 전달했다.
- [ ] OpenAPI 문서를 최신으로 유지했다.

## 5. 테스트
### 5.1 단위 테스트
- [ ] 빈 이미지 입력 테스트를 작성했다.
- [ ] 잘못된 포맷 입력 테스트를 작성했다.
- [ ] 얼굴 미검출/다중 얼굴 테스트를 작성했다.
- [ ] 정상 이미지 임베딩 생성 테스트를 작성했다.

### 5.2 통합 테스트
- [ ] Back에서 AI를 실제 호출하는 E2E 테스트를 통과했다.
- [ ] 등록/검색 시나리오 테스트를 통과했다.
- [ ] 동시 요청 부하 테스트를 수행했다.

### 5.3 정확도 테스트
- [ ] 평가셋 기준 FAR/FRR/TPR/FPR 리포트를 생성했다.
- [ ] threshold 튜닝 리포트를 공유했다. (현재 운영값 0.7)

## 6. 성능 최적화
- [ ] 모델 재로딩 없이 재사용되도록 확인했다.
- [ ] 입력 이미지 크기 가이드를 제시했다. (권장 해상도/용량)
- [ ] p95 latency와 timeout 비율을 측정했다.
- [ ] 병목 지점을 문서화했다. (디코딩/추론/네트워크)

## 7. 보안/개인정보 점검
- [ ] 원본 이미지 파일 저장 코드가 없는지 점검했다.
- [ ] 이미지/임베딩 민감 로그가 출력되지 않는지 점검했다.
- [ ] 내부 API 인증 헤더 검증 로직을 적용했다.
- [ ] TLS(또는 내부망+mTLS) 적용 상태를 확인했다.
- [ ] 접근 권한(RBAC)과 감사로그 정책을 확인했다.

## 8. 배포 준비
- [ ] Docker 이미지 빌드/실행이 재현 가능하다.
- [ ] 헬스체크 엔드포인트를 제공한다. (`/health`)
- [ ] readiness/liveness 기준을 정의했다.
- [ ] 배포/롤백 절차를 문서화했다.
- [ ] 모델 버전 표기 규칙을 문서화했다.

## 9. 운영 모니터링
- [ ] 모니터링 지표를 수집한다. (요청수, 성공률, 에러율, p95)
- [ ] 장애 알람 조건을 설정했다.
- [ ] 주요 에러코드별 대응 Runbook을 작성했다.
- [ ] 정기 정확도 점검 주기를 합의했다.

## 10. 인수인계
- [ ] API 명세서(OpenAPI) 전달 완료
- [ ] 환경변수/시크릿 목록 전달 완료
- [ ] 운영 가이드 전달 완료
- [ ] 장애 대응 가이드 전달 완료
- [ ] 정확도/성능 리포트 전달 완료

## 11. 완료 기준 (Definition of Done)
- [ ] Back이 AI API를 사용해 등록/검색 기능을 정상 제공한다.
- [ ] 원본 이미지 비저장 정책이 코드/운영에서 검증되었다.
- [ ] 합의된 SLA 내에서 안정적으로 동작한다.
- [ ] 문서(OpenAPI/운영/보안/테스트)가 최신 상태다.
