# AI-012 월간 소비 인사이트 구현

## 개요

이 구현은 SSAFY 카드 거래내역을 기반으로 월간 소비 리포트를 생성하고, 결과를 기존 `consumption_report` 테이블에 저장합니다.

- 거래 원천 데이터: SSAFY 카드 결제 내역 조회 API
- 카테고리 정규화: AI-011 카테고리 분류 흐름 재사용
- 인사이트 생성: AI 월간 한 줄 조언 API
- 저장 대상: 기존 `consumption_report`
- 현재 집계 범위: 사용자 활성 카드 전체

## 프론트 사용 방식

프론트에서는 이 결과를 요약 카드 1개 형태나 대표 계좌/카드 영역처럼 표시할 수 있습니다.

다만 현재 백엔드 동작 기준은 아래와 같습니다.

- 사용자당 월간 리포트 1개 생성
- 해당 사용자의 활성 신용카드/체크카드 전체를 합산해 집계
- 특정 대표 카드 1장만 대상으로 하지는 않음
- 특정 대표 계좌 1개만 대상으로 하지는 않음

즉 화면은 카드 하나처럼 보여줄 수 있지만, 실제 데이터 범위는 현재 `사용자 단위 월간 카드 소비`입니다.

## 처리 흐름

1. 클라이언트가 `POST /api/reports/monthly/generate?userNo={userNo}&targetMonth={yyyy-MM}` 호출
2. 백엔드가 해당 사용자의 활성 신용카드/체크카드 조회
3. 백엔드가 각 카드별로 SSAFY 카드 거래조회 API 호출
4. 기존 AI-011 흐름으로 각 거래의 `aiCategory` 분류
5. 백엔드가 월간 카테고리별 지출 합산
6. 백엔드가 집계 결과를 AI 월간 인사이트 API에 전달
7. AI가 한 줄 조언 생성
8. 백엔드가 `consumption_report`에 월간 리포트 저장 또는 갱신

## AI 구현

### 신규 내부 API

- `POST /internal/v1/consumption/reports/monthly/insights`

### 입력값

- `periodStart`
- `periodEnd`
- `totalSpending`
- `categoryBreakdown`
- `previousTotalSpending` (선택)
- `previousCategoryBreakdown` (선택)

### 출력값

- `insights`
- `modelVersion`

### 인사이트 생성 방식

현재 구현은 규칙 기반이며, 한 줄 조언만 반환합니다.

예시:

- 카페 비중이 큰 경우: `이번 달 카페 지출이 많았어요. 커피 한두 잔만 줄여도 절약 효과가 분명해요.`
- 식비 비중이 큰 경우: `이번 달 식비 비중이 높았어요. 외식 횟수를 조금만 줄여도 부담을 낮출 수 있어요.`
- 지난달 대비 증가한 경우: `이번 달 카페 지출이 지난달보다 늘었어요. 자주 가는 커피 소비를 한 번 점검해보세요.`

## 백엔드 구현

### 신규 공개 API

- `POST /api/reports/monthly/generate`

쿼리 파라미터:

- `userNo`
- `targetMonth` (`yyyy-MM`)

### 백엔드 역할

- SSAFY에서 월간 카드 거래내역 조회
- 사용자의 활성 카드 전체 거래 수집
- 기존 AI-011 분류 흐름 재사용
- `transactionUniqueNo` 기준 중복 제거
- `aiCategory` 기준 카테고리별 지출 집계
- AI 월간 인사이트 API 호출
- `consumption_report`에 월간 리포트 upsert 저장

### 저장 방식

월간 리포트 생성은 기존 데이터가 있으면 갱신하고, 없으면 새로 저장하는 방식으로 구현했습니다.

- 같은 사용자/같은 월 리포트가 이미 있으면 갱신
- 없으면 새 리포트 생성

## 참고 사항

- 현재 버전에서는 `localSpending`, `localRatio`, `localGrade`를 `null`로 저장합니다.
- 이유는 SSAFY 카드 거래 응답만으로는 지역 소비 여부를 안정적으로 계산하기 어렵기 때문입니다.
- 이번 버전은 카테고리 집계와 한 줄 조언 생성에 집중합니다.
- 추후 요구사항이 `대표 카드 1장 기준` 또는 `대표 계좌 1개 기준`으로 바뀌면, 백엔드 집계 범위를 별도로 좁혀야 합니다.
