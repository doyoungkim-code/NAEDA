# AI-011 카테고리 분류 기능 구현

## 개요

이 문서는 AI 서버와 백엔드에 구현한 `AI-011 카테고리 분류` 범위를 정리한 문서입니다.

- 목표: 카드 거래 1건마다 서비스용 소비 카테고리를 정규화해 분류
- 저장 기준:
  - `transaction_log.category`: SSAFY 원본 카테고리 유지
  - `transaction_log.ai_category`: AI가 정규화한 카테고리 저장
- 프론트 사용 방식: 이후 프론트는 AI 서버를 직접 호출하지 않고, 백엔드 응답의 `aiCategory`만 사용하면 됩니다.

## AI 구현

### 추가된 내부 API

- 엔드포인트: `POST /internal/v1/consumption/categories/classify`
- 인증: `X-Service-Token`
- 요청 예시:

```json
{
  "transactions": [
    {
      "transactionId": "TX-1",
      "merchantName": "스타벅스 구미역점",
      "rawCategory": "생활",
      "memo": "승인",
      "amount": 5900,
      "transactedAt": "2026-03-13T09:30:00"
    }
  ]
}
```

- 응답 예시:

```json
{
  "results": [
    {
      "transactionId": "TX-1",
      "aiCategory": "카페",
      "confidence": 0.73,
      "fallbackUsed": false
    }
  ],
  "modelVersion": "consumption-rule-v1"
}
```

### 분류 방식

현재 구현은 `v1 규칙 기반 분류기`입니다.

- 원본 카테고리 매핑:
  - 예: `교육/육아 -> 교육`, `대형마트 -> 마트`, `통신 -> 주거/통신`
- 가맹점 키워드 보정:
  - 예: `스타벅스 -> 카페`, `카카오택시 -> 교통`, `이마트 -> 마트`
- 보정 처리:
  - 강한 가맹점 키워드가 없으면 원본 카테고리 정규화 결과 또는 `기타`로 분류

별도 학습 데이터셋 없이 바로 동작할 수 있도록 의도적으로 가볍게 구현했습니다.

## 백엔드 구현

### DB 및 엔티티 변경

`transaction_log`에 `ai_category` 컬럼을 추가했습니다.

```sql
ai_category VARCHAR(30)
```

의미는 아래와 같습니다.

- `category`: SSAFY 원본 카테고리
- `ai_category`: AI 정규화 카테고리

### 백엔드 처리 흐름

1. SSAFY 카드 거래내역 조회
2. 백엔드에서 전체 거래 파싱
3. `aiCategory`가 없는 거래만 AI 서버에 배치 분류 요청
4. 백엔드 저장 시
   - 원본 카테고리는 `category`에 저장
   - 정규화 카테고리는 `aiCategory`에 저장
5. 이미 캐싱된 거래는 재사용
6. AI 호출 실패 시 로컬 보정 매퍼로 대체하여 카드 거래 조회가 실패하지 않도록 처리

### 응답 필드 노출

`aiCategory`는 아래 응답에 포함됩니다.

- 카드 거래 조회 응답
- 거래내역 조회 응답

이후 프론트는 백엔드 API 응답만 이용하면 됩니다.

## 참고 사항

- 현재 카테고리 분류기는 학습형 ML 모델이 아니라 규칙 기반입니다.
- 현재 스프린트에서는 SSAFY가 제공하는 원본 카테고리를 기반으로 정규화/보정하는 것이 목적이라 이 방식이 적절합니다.
- 추후 라벨 데이터가 충분히 쌓이면, 백엔드 계약을 바꾸지 않고도 TF-IDF + Logistic Regression 같은 지도학습 모델로 교체할 수 있습니다.
