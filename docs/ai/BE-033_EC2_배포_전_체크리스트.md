# BE-033 EC2 배포 전 체크리스트

## 목적

이 문서는 `BE-033 신분증 OCR 검증 API`를 `EC2 Linux`에 올리기 전에 확인해야 할 항목을 정리한 체크리스트다.

현재 기능의 마지막 불확실성은 `EC2 Linux`에서 `PaddleOCR`가 실제로 정상 추론되는지 여부이므로, 배포 전에 아래 항목을 준비해두는 것이 중요하다.

## 1. 아키텍처 확인

- [ ] OCR 추론 책임은 `AI` 서비스에 둔다.
- [ ] `BE`는 `AI` 내부 OCR API만 호출한다.
- [ ] 외부 공개는 `BE`만 하고 `AI`는 내부 통신만 허용한다.
- [ ] 초기 배포는 `단일 EC2 + BE/AI 분리 컨테이너` 구조로 간다.

## 2. EC2 인프라 준비

- [ ] `Ubuntu` 등 Linux 기반 EC2 인스턴스가 준비되어 있다.
- [ ] Docker가 설치되어 있다.
- [ ] Docker Compose 실행 환경이 준비되어 있다.
- [ ] 보안 그룹에서 `BE` 공개 포트만 외부 허용한다.
- [ ] `AI` 포트 `8000`은 외부 공개하지 않거나 최소 범위만 허용한다.
- [ ] 디스크 용량이 모델 다운로드와 로그 저장을 감당할 수 있다.

권장:

- CPU 기반이면 최소 `2 vCPU / 4GB RAM` 이상에서 시작
- 여유가 있으면 `4 vCPU / 8GB RAM`이 안정적

## 3. AI 컨테이너 준비

- [ ] `AI` Docker 이미지가 빌드된다.
- [ ] `AI` 컨테이너가 Linux에서 정상 기동된다.
- [ ] `paddleocr` 패키지가 이미지에 포함되어 있다.
- [ ] OpenCV 및 런타임 의존성이 이미지에 포함되어 있다.
- [ ] 모델 캐시 경로를 영속 볼륨으로 마운트한다.
- [ ] `PADDLE_HOME` 또는 `RESIDENT_OCR_PADDLE_HOME` 경로가 쓰기 가능하다.

환경 변수:

- [ ] `RESIDENT_OCR_PROVIDER=paddleocr`
- [ ] `RESIDENT_OCR_PADDLE_LANG=korean`
- [ ] `RESIDENT_OCR_MIN_CONFIDENCE` 값이 설정되어 있다.
- [ ] `RESIDENT_OCR_PADDLE_HOME=/app/.paddle` 등 Linux 경로로 설정되어 있다.
- [ ] `INTERNAL_SERVICE_TOKEN`이 설정되어 있다.
- [ ] `APP_HOST=0.0.0.0`
- [ ] `APP_PORT=8000`
- [ ] `APP_RELOAD=false`

## 4. BE 컨테이너 준비

- [ ] `BE` Docker 이미지가 빌드된다.
- [ ] `BE` 컨테이너가 정상 기동된다.
- [ ] `BE`에서 `AI` base URL을 내부 주소로 설정했다.
- [ ] `BE`와 `AI`가 같은 Docker network 또는 내부 네트워크로 통신한다.
- [ ] `BE`의 `AI service token`과 `AI`의 `INTERNAL_SERVICE_TOKEN` 값이 일치한다.
- [ ] `BE -> AI` 타임아웃이 설정되어 있다.

환경 변수:

- [ ] `ai.base-url` 또는 `AI_BASE_URL=http://ai-internal:8000`
- [ ] `ai.service-token` 또는 `AI_SERVICE_TOKEN`
- [ ] `ai.timeout-seconds=5` 수준으로 설정

## 5. 기능 플래그 및 운영 모드 확인

- [ ] 로컬 개발에서는 `RESIDENT_OCR_PROVIDER=mock`를 유지한다.
- [ ] EC2에서는 `RESIDENT_OCR_PROVIDER=paddleocr`로 바꾼다.
- [ ] 필요 시 장애 대응용으로 `mock` 또는 다른 provider로 전환 가능한 구조를 유지한다.

## 6. 데이터 및 보안 확인

- [ ] 신분증 원본 이미지를 장기 저장하지 않는 정책이 정리되어 있다.
- [ ] 로그에 주민번호 전체가 남지 않도록 마스킹 정책이 있다.
- [ ] OCR 응답 실패 시 사용자에게 노출할 메시지가 정리되어 있다.
- [ ] 서비스 간 인증 토큰을 코드에 하드코딩하지 않는다.
- [ ] `.env` 또는 시크릿 관리 방식이 정리되어 있다.

## 7. 배포 전 로컬 확인 항목

- [ ] `mock` 기준 `extract API`가 정상 응답한다.
- [ ] `mock` 기준 `confirm API`가 정상 응답한다.
- [ ] `BE -> AI` 호출 시 예외 코드 매핑이 정상 동작한다.
- [ ] 이미지 형식 오류, 빈 파일, 용량 초과 예외가 기대대로 내려간다.
- [ ] OCR 결과 DTO 필드명이 프런트 기대값과 일치한다.

## 8. 운영 관측성 준비

- [ ] `AI` health check가 준비되어 있다.
- [ ] `BE`에서 `AI` 호출 실패 로그가 남는다.
- [ ] `AI`에서 OCR 소요 시간과 실패 코드 로그가 남는다.
- [ ] 요청 추적용 request ID 또는 유사한 상관관계 키를 남길 수 있다.

## 9. 배포 직전 최종 체크

- [ ] `AI` 컨테이너 실행 후 health check가 통과한다.
- [ ] `BE` 컨테이너 실행 후 API 기동이 확인된다.
- [ ] `BE`에서 `AI` 내부 주소로 네트워크 접근이 된다.
- [ ] `X-Service-Token` 인증이 정상 동작한다.
- [ ] 샘플 신분증 이미지로 최소 1회 실제 OCR 테스트를 수행할 준비가 되어 있다.

## 10. 완료 기준

아래 조건을 만족하면 `BE-033`은 배포 검증 단계로 진입할 준비가 끝난 상태로 본다.

- [ ] `BE`와 `AI` 컨테이너가 EC2에서 모두 기동 가능
- [ ] `BE -> AI` 내부 호출 설정 완료
- [ ] `AI`가 `paddleocr` provider로 실행 가능
- [ ] 배포 후 검증 시나리오 수행 준비 완료
