# AI-003 성능 측정/튜닝 리포트

## 1. 측정 대상
- BE 엔드포인트: `POST /api/v1/face/liveness/headpose/check`
- 호출 경로: `Front -> BE -> AI -> BE -> Front`
- 샘플 수: 60회(순차 호출)
- 테스트 이미지: `AI/.venv/insightface/data/images/t1.jpg`
- 응답 코드: `400(NO_FACE)` 경로 기준 지연 측정

## 2. 기준선(Baseline)
- `avg`: `2709.44 ms`
- `p50`: `2791.39 ms`
- `p95`: `2922.15 ms`
- `min/max`: `2198.90 / 3069.21 ms`
- 코드 분포: `400:60`

## 3. 튜닝 적용

### 적용 내용
- ArcFace detector size 설정값 추가 및 축소
  - `arcface_det_size` 설정 추가 (기본 `320`)
  - 기존 고정값 `640` -> 설정값 사용

### 변경 파일
- `AI/app/core/config.py`
- `AI/app/core/arcface.py`

## 4. 튜닝 후 측정
- `avg`: `2409.69 ms`
- `p50`: `2659.99 ms`
- `p95`: `2820.89 ms`
- `min/max`: `1649.80 / 2844.63 ms`
- 코드 분포: `400:60`

## 5. 개선 효과
- 평균 지연: `2709.44 -> 2409.69 ms` (`-299.75 ms`, 약 `11.1%` 개선)
- p50 지연: `2791.39 -> 2659.99 ms` (`-131.40 ms`, 약 `4.7%` 개선)
- p95 지연: `2922.15 -> 2820.89 ms` (`-101.26 ms`, 약 `3.5%` 개선)

## 6. 다음 개선 우선순위
1. 다중 프레임 API 지원
- 단일 프레임 N회 호출 대신 배치/시퀀스 입력으로 왕복 횟수 감소

2. 이미지 전처리 경량화
- BE에서 업로드 이미지를 320~480px로 리사이즈 후 AI 전달

3. 비동기/병렬 처리 최적화
- BE에서 요청 큐/timeout/retry 정책 분리
- AI 추론 워커 수 조정(코어 수 기반)

4. 정확도-속도 프로파일링 분리
- 운영 프로필(`det_size=320`) / 고정밀 프로필(`det_size=640`) 분리 운영

## 7. 참고
- 현재 측정은 `NO_FACE` 응답 경로 기준이다.
- 실서비스에서는 실제 얼굴 입력(정상 200 응답) 기준 p50/p95를 추가 측정해야 한다.
