# Git Convention

## 1. 브랜치 전략 (Git Flow)

```
master ── 배포 가능한 상태 유지
  └── dev ── 개발 통합 브랜치
        ├── feat/기능명 ── 새 기능 개발
        ├── fix/버그명 ── 버그 수정
```

### 브랜치 네이밍

| 브랜치 | 형식 | 예시 |
|--------|------|------|
| 기능 개발 | `feat/[담당]/#이슈번호-기능명` | `feat/FE/#12-login-page` |
| 버그 수정 | `fix/[담당]/#이슈번호-버그명` | `fix/BE/#25-token-expire` |

- 담당: `FE`, `BE`, `AI`, `INFRA`
- 브랜치명은 **영문 소문자, 하이픈(-)** 사용

### 브랜치 흐름

1. `dev`에서 작업 브랜치 생성
2. 작업 완료 후 `dev`로 MR(Merge Request)
3. 코드 리뷰 후 머지
4. 스프린트 종료 시 `dev` → `master` 머지

## 2. 커밋 메시지

### 형식

```
[담당]타입: 제목
```

### 타입

| 타입 | 담당 접두사 | 설명 | 예시 |
|------|:-----------:|------|------|
| `feat` | O | 새로운 기능 추가 | `[FE]feat: 로그인 페이지 구현` |
| `fix` | O | 버그 수정 | `[BE]fix: JWT 토큰 만료 처리 수정` |
| `refactor` | O | 리팩토링 (기능 변경 없음) | `[FE]refactor: 컴포넌트 구조 개선` |
| `style` | O | 코드 포맷팅, 세미콜론 등 | `[BE]style: prettier 적용` |
| `test` | O | 테스트 코드 | `[BE]test: 결제 API 단위 테스트 추가` |
| `chore` | O | 빌드, 설정 파일 변경 | `[Infra]chore: Docker 설정 추가` |
| `design` | O | UI/UX 변경 (CSS 등) | `[FE]design: 메인 페이지 반응형 적용` |
| `init` | O | 프로젝트 초기 설정 | `[BE]init: Spring Boot 프로젝트 생성` |
| `docs` | X | 문서 추가/수정 | `docs: API 명세 작성` |

### 규칙

- 담당: `[FE]`, `[BE]`, `[AI]`, `[Infra]`
- `docs`는 담당 접두사 없이 사용
- 제목은 **한글**로 작성
- 제목 끝에 마침표(.) 사용하지 않음

---

## 3. MR (Merge Request)

### 제목

```
[담당]타입: 제목
```

예시: `[FE]feat: 얼굴 인식 결제 화면 구현`

### 본문 템플릿

```markdown
## 작업 내용
- 변경 사항 요약

## 관련 이슈
- #이슈번호

## 스크린샷 (선택)

## 리뷰 요청 사항 (선택)
```

### 규칙

- `dev` 브랜치로만 MR 생성
- 최소 1명 이상 코드 리뷰 후 머지
- 머지 후 작업 브랜치 삭제

---

## 4. .gitignore 주의 사항

커밋하지 않는 파일:
- `.env`, `application-secret.yml` 등 환경 변수 / 시크릿
- `node_modules/`, `build/`, `.gradle/` 등 빌드 산출물
- IDE 설정 파일 (`.idea/`, `.vscode/`)
